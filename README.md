# ❄️ Modular NixOS Configuration

A clean, scalable, and fully modular NixOS configuration powered by **Flakes** and **Home Manager**. Designed with a strict "single source of truth" philosophy to decouple hardware, system services, user identities, and application packages.

---

## 📂 Repository Architecture

```text
.
├── flake.nix                          # Master orchestrator: defines flake inputs, host outputs, and user bindings
├── flake.lock                         # Pinned dependency lockfile ensuring reproducible builds across systems
├── hardware-configuration.nix         # Machine-specific hardware specifications generated by nixos-generate-config
├── README.md                          # Repository documentation and architectural guide
├── common/                            # Universal configurations shared across all machines
│   ├── nixos.nix                      # Core Nix daemon settings, bootloader, GC, and flakes enablement
│   ├── home.nix                       # Base Home Manager blueprint common to all user environments
│   ├── packages.nix                   # Universal system CLI tools and core system package imports
│   ├── services.nix                   # Essential shared system services (PipeWire, NetworkManager, Udisks2)
│   ├── env_variables.nix              # Global system-wide environment & session variables
│   ├── xdg.nix                        # Standard XDG user directory layout (Downloads, Documents, etc.)
│   ├── ssh-key.nix                    # Automated user Ed25519 SSH key generation service and ssh-agent
│   ├── locale/
│   │   └── india.nix                  # System timezone (Asia/Kolkata), internationalization, and locale settings
│   └── display_manager/
│       └── greetd.nix                 # Lightweight display manager configuration using Tuigreet
├── hosts/                             # Machine-specific entry points
│   └── desktop/                       # Host profile for target machine ("nixos")
│       ├── configuration.nix          # Host-level system assembly combining common and host modules
│       ├── sys-packages.nix           # Host-specific system-level services and packages (Steam, Ollama, Nginx)
│       ├── hardware.nix               # Hardware profile importer (links to GPU and platform profiles)
│       ├── filesystem.nix             # Mount points, btrfs subvolumes, and swap file definitions
│       ├── packages.nix               # User application bundle and personal dev modules for this host
│       └── env-variables.nix          # Host-specific user session environment variables (e.g. EDITOR)
├── hardware/                          # Modular, reusable hardware profiles
│   └── gpu/
│       └── radeon.nix                 # AMD GPU graphics drivers, Mesa OpenCL, Vulkan, and diagnostic tools
├── modules/                           # Custom declarative option modules
│   └── dev/
│       └── cpp.nix                    # (Sample) Custom C/C++ development toolchain module with toggle options
├── packages/                          # Modular standalone application configs
│   └── neovim.nix                     # (Sample) Standalone application package and configuration module
└── users/                             # User identity declarations
    └── stranger.nix                   # (Sample) User identity metadata, account specifications, and module exports
```

## 📖 Component Documentation

### ⚙️ Root Files

- **`flake.nix`**: The primary entry point for the entire repository. Declares flake inputs (`nixpkgs`, `home-manager`), imports user definitions, and exports NixOS host configurations (`nixosConfigurations.<hostname>`) linking system and Home Manager modules together.
- **`flake.lock`**: Flake dependency lockfile tracking exact Git commit hashes and integrity digests of all inputs, ensuring bit-for-bit reproducibility.
- **`hardware-configuration.nix`**: Low-level hardware configuration auto-generated by `nixos-generate-config`. Manages kernel modules, initrd drivers, CPU microcode, and root filesystem mounts.

---

### 🌐 Universal Base Configurations (`common/`)

Shared configurations applied to all systems regardless of form factor or hardware:

- **`common/nixos.nix`**: Configures systemd-boot EFI bootloader, enables experimental Nix features (`flakes` and `nix-command`), and defines automatic storage optimization and weekly garbage collection (`nix.gc`).
- **`common/home.nix`**: The shared Home Manager baseline applied to user sessions. Binds the dynamic username and home directory path, sets the state version, and enables Home Manager itself.
- **`common/packages.nix`**: Installs baseline system-level command-line utilities (`curl`, `wget`, `jq`, `vim`, `btrfs-progs`) and imports baseline package configs like Fish shell, core fonts, and PipeWire.
- **`common/services.nix`**: Manages essential system-level daemons including Polkit, Rtkit, NetworkManager, Udisks2 (automounting), GVFS, Tumbler (file thumbnails), and UPower (power management). Imports SSH key automation.
- **`common/env_variables.nix`**: Global environment variables applied system-wide, such as the default system editor (`EDITOR = "nvim"`) and Wayland Ozone enablement (`NIXOS_OZONE_WL = "1"`).
- **`common/xdg.nix`**: Manages declarative XDG user directories (`Downloads`, `Documents`, `Pictures`, `Music`, `Videos`, etc.) via Home Manager.
- **`common/ssh-key.nix`**: Defines a one-shot systemd service that automatically generates an Ed25519 SSH keypair in the user's `~/.ssh` directory on boot if one does not exist, and starts the SSH agent daemon.
- **`common/locale/india.nix`**: Sets the system timezone to `Asia/Kolkata` and configures internationalization (`en_US.UTF-8` default with `en_IN` regional formatting for numbers, currency, and dates).
- **`common/display_manager/greetd.nix`**: Configures `greetd` using `tuigreet` as a console-based display manager to launch the Hyprland desktop session via UWSM.

---

### 🖥️ Host Configurations (`hosts/`)

Machine-specific entry points that assemble universal defaults with machine-specific resources:

- **`hosts/desktop/configuration.nix`**: The primary system coordinator for the "desktop" host. Imports common system configurations, host hardware, file systems, host system packages, sets the hostname (`nixos`), D-Bus broker, and system state version.
- **`hosts/desktop/sys-packages.nix`**: Host-level packages and system daemons tailored to this workstation, including Nginx, Ollama, Steam, and system-level Hyprland compositing.
- **`hosts/desktop/hardware.nix`**: Declares host hardware profile inclusions (such as importing AMD GPU driver configs).
- **`hosts/desktop/filesystem.nix`**: Declares host-specific storage mounts (e.g. secondary btrfs pools for Steam storage) and swapfile allocation.
- **`hosts/desktop/packages.nix`**: Assembles the complete userland environment for this workstation via Home Manager, selecting active user packages (browsers, terminals, media players, tools) and enabling custom dev modules.
- **`hosts/desktop/env-variables.nix`**: Machine-specific user session environment variables (e.g. user-level `EDITOR` bindings).

---

### 🎛️ Reusable Hardware Profiles (`hardware/`)

Modular hardware profiles that can be shared across any host equipped with corresponding devices:

- **`hardware/gpu/radeon.nix`**: Configures AMD Radeon graphics support, Mesa 32-bit/64-bit drivers, OpenCL compute runtimes, initrd kernel modules (`amdgpu`), and diagnostic monitoring utilities (`lact`, `amdgpu_top`, `clinfo`, `vulkan-tools`).

---

### 📦 Modular Directories (Patterns & Samples)

- **`packages/`**: Isolated, self-contained configuration files for individual applications and tools (e.g. `neovim.nix`, `kitty.nix`, `hyprland.nix`, `mpv.nix`, `git.nix`). Each file configures one specific package or dotfile, keeping application logic completely modular.
  - *Sample (`packages/neovim.nix`)*: Configures Neovim alongside its required plugins, treesitter parsers, and custom Lua init configuration.
- **`modules/`**: Custom reusable NixOS or Home Manager option modules that provide feature toggles via `options` and `config = lib.mkIf ...`.
  - *Sample (`modules/dev/cpp.nix`)*: Custom development environment module providing `myCustom.dev.cpp.enable` to install the Clang/LLVM toolchain, CMake, Ninja, GDB, Valgrind, and set standard compiler variables.
- **`users/`**: Single source of truth for user identities. Defines account metadata and exports system and Home Manager modules.
  - *Sample (`users/stranger.nix`)*: Exports user metadata (`username`, `fullName`, `email`) and creates the system user account with default groups (`wheel`, `networkmanager`, `audio`) and Fish login shell.

## 🏛️ Design Philosophy

This repository is structured around four foundational architectural pillars:

1. **Single Source of Truth (SSOT)**:  
   User metadata (username, full name, email) and system account specifications are encapsulated within their own dedicated files (e.g., `users/stranger.nix`). These fields are exported upward and dynamically injected into both NixOS and Home Manager via `flake.nix`. Changing identity details in one place propagates automatically across the entire system.

2. **Strict Separation of Concerns**:
   - **System vs. User**: Low-level system daemons, hardware drivers, and kernel parameters live in system configurations, while user applications, dotfiles, and shell preferences are handled via Home Manager.
   - **Universal vs. Host-Specific**: `common/` holds bare-minimum settings that apply universally. `hosts/` isolates machine-specific capabilities (such as heavy GPUs, secondary storage pools, or host-tailored system packages like Steam and Ollama).

3. **Symmetrical Scalability**:  
   Adding a new machine or a new user follows a repeatable, predictable pattern. Deploying to a laptop in the future will only require creating a new `hosts/laptop/` directory while reusing the exact same `common/` infrastructure and `users/` definitions.

4. **Modular Composition**:  
   Instead of massive, monolithic configuration files, every application (`packages/neovim.nix`, `packages/yazi.nix`, etc.) and system module is isolated into its own file. Features are enabled simply by pulling them into an import list like building blocks.

## 🚀 Usage & Rebuilding

### Apply Configuration Changes
To update or rebuild your system configuration using this flake, run:
```bash
sudo nixos-rebuild switch --flake /etc/nixos#nixos
```

### Update Flake Inputs
To update locked flake dependencies (e.g. nixpkgs, home-manager):
```bash
nix flake update
```

### Garbage Collection & Optimization
To clean up old system and user generations and optimize storage:
```bash
sudo nix-collect-garbage --delete-older-than 7d
```
